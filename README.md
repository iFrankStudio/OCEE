# OCEE — 开放式演化赛博生态世界

**规范基线：v0.2.0 · 工程：P1/P2/P3 + S0–S6 开发基线，CI 39 项通过 · E001 尚未校准、未预注册**

OCEE 是与 CIOC/CL 系列**相互独立**的研究路线。其长期目标是探索一种能够适应未知数字环境、学习使用现有软硬件与网络服务、创造新工具并持续改进自身的赛博生命培养机制。

首个原型 **OCEE-0** 不宣称创造出生命，也不将一般编程智能体得分等同于开放式演化。它先检验一个可证伪命题：

> 带有明确声明的通用初始能力的个体，能否在可重放的陌生协议环境中，自行产生并保存此前不具备的可复用程序能力，并将其迁移到结构不同的新环境？

## 首个实验与主体类型

**E001 — 未知计算资源的自主发现与利用**

- Node A：个体的本地计算/存储环境。
- Node B：额外的受限远程计算/存储资源，不允许直连。
- Node C：未知编码的消息服务入口，按可学的有限协议家族解析并访问 B。
- **S 型（Seeded）**：人工赋予一般性探索、候选生成、可见反馈选择和经验记录能力；四组 A/B/C/D 比较固定、随机、短期适应、跨 episode 累积。
- **O 型（Origin）**：不预设高阶探索目标，单独研究探索驱动力是否形成；不与 S 的主实验效应混合统计。

即使 E001 成功，也只是支持在给定先验与环境下的一类可积累适应机制，**不代表已经证明数字生命、意识或无限开放式演化**。

## 从工程开工到科学结论：三个不同闸门

| 闸门 | 当前状态 | 通过含义 |
|---|---|---|
| **G0 Engineering GO** | **已达到** | 执行语义与工程接口足以启动内核、VM、服务实现 |
| **G1 Calibration GO** | 未达到 | 代码实际通过核心行为测试，初始程序/独立求解器就绪，可开始 E001 开发集校准 |
| **G2 Confirmatory GO** | 未达到 | 校准通过、正式 seed 封存、门槛和统计脚本冻结且预注册，才可以运行确认性实验 |

建议的最小实施顺序：

1. 实现 Rust 确定性世界内核、快照和日志（仅保留关键不变量测试）。
2. 实现受限类型化 VM、自我修改与版本存储。
3. 实现 A/B/C 模拟节点、P0/P1/P2 协议向量和 FOLD32 独立参考实现。
4. 构建 S 初始程序和四组机制开关、O 的独立基线；生成并审计不可变能力 manifest。
5. 运行独立可学性校准（开发 seed），评估资源权衡与统计功效。
6. 根据校准结果版本化修订必要参数；冻结正式配置，运行 E001 并保留包括失败在内的所有结果。

## 当前工程进度：P1/P2/P3 开发切片

- Rust 世界内核：[world-kernel](./crates/world-kernel/)；受限 VM：[organism-vm](./crates/organism-vm/)；协议模拟器：[protocol-sim](./crates/protocol-sim/)。
- [最新已验证 CI Run #44118404623](https://github.com/iFrankStudio/OCEE/actions/runs/44219065880)：**39 项关键测试通过，0 项失败**。覆盖时序、权限/资源、状态重放、程序版本与回退、隔离只读、受限循环、三种未知协议的报文处理与 FOLD32 远程服务。
- [工程检查点与尚未完成的工作](./07-ENGINEERING-CHECKPOINT.md) 区分实现证据与实验结论：端到端样例使用研究者准备的程序及合法协议报文，**不能算作自发探索、真实新能力创造或 E001 成功**。
- 已实现真正以 VM 世界动作为主导的 [S0 观察/重放个体与 S1 P0 反馈探测个体](./experiments/E001/DEV-S0-S1.md)。S0 可以跨 P0/P1/P2 利用公开样例；S1 在已知 P0 XOR 规则但未知目标操作码的条件下，通过可见错误反馈识别操作码，诊断屏蔽对照不产生同一发现。**S0 和原版 S1 依旧没有新程序生成；派生工具实验见 S3，尚无跨家族迁移证据。**
- [S2 P0 远程工作项开发实验](./experiments/E001/DEV-S2.md)：从 S1 持久发现构造有效 FOLD32 请求，主动搜索 RESULT 操作码并保存计算结果；**S2 仍由研究者在阶段边界安装，不是自主创生工具**。
- [S3 个体内部工具派生与采用](./experiments/E001/DEV-S3-SPECIALIZATION.md)：同一活动 VM 个体依据 S1 发现的操作码派生出可执行报文构造工具，自己测试、注册并用于公开工作项；该工具在两种不同输入长度下复用成功。**生成算法模板仍由研究者预置，这不是新算法发明。**
- [S4 结构修复研究](./experiments/E001/DEV-S4-STRUCTURAL-REPAIR.md)：同一个 VM 个体先产生可执行但功能错误的程序，随后在输出验证失败后改写指令节点并验证成功；结构修复关闭时无法注册工具。**两种候选及验证策略依然人工预置，不是开放式算法发明。**
- [S4 标准资源配额开发校准](./experiments/E001/DEV-S4-RESOURCE-CALIBRATION.md)：同一初始程序在 4 个开发 seed 下，12,000 与 100,000 A gas/epoch 两种配置均完成；标准配置其中 3 个 seed 出现 666～673 次资源拒绝，不能把等待资源的逻辑步数算作有效探索。
- [S5 数据样例驱动的操作符搜索](./experiments/E001/DEV-S5-OPERATOR-SEARCH.md)：同一初始个体根据公开输入输出样例，在三种已赋予原语中选取程序结构；六个开发种子覆盖三类隐藏规则、保留输入验证通过，单候选对照按预期失败。**这是 E001 辅助的封闭词表实验，并非 P1/P2 协议结构学会或新算法发明。**
- [S6 有限语法内的多节点组合](./experiments/E001/DEV-S6-COMPOSITION.md)：在预置的 3 种一元与 2 种二元原语中搜索共 18 种表达式结构，同一个 VM 程序在六个开发种子下通过保留输入核验；禁用第二个计算输入的对照无法解决真正的组合任务。**仍为预置语法，不构成 E001 正式协议学习证据。**
- [S6 资源与泛化复核](./experiments/E001/DEV-S6-COMPOSITION.md)：三种子在标准 12,000 gas/epoch 配额下成功完成、无 gas 拒绝；对六组开发程序各四个未见非空输入复验通过，同时确认空输入令部分含 ByteAt 工具越界。**有限泛化成功不等于整个 Bytes 域正确。**
- G0 Engineering GO；G1 Calibration **NO-GO**；G2 Confirmatory **NO-GO**。仍缺完整 S/O 基线、P2 结构性可学习性、工作项和 A/B/C/D 对照、独立校准、事务持久化及安全复核。
- 运行关键测试：`cargo test --workspace`。仅在实现新核心不变量时增加必要测试，避免测试膨胀。

## 基本安全与科学诚信约束

- 不访问公网、真实生产系统、宿主文件或实体执行器。以后要接入真实软件必须建立单独授权网关。
- 世界内核/外部评价器/安全边界不允许被个体写入或自我修改。
- 不强制生物式繁殖、寿命或“生命值”；资源耗尽意味着动作受阻，不等于死亡。
- 仅当工具经过功能复验和来源审计，才可能计为新能力；复杂代码、变异次数和高分本身不足以证明演化。
- 环境校准样本与正式样本必须隔离；禁止失败后修改正式门槛并继续把结果称为同一次确认性实验。
- 只为确定性、权限、计费、版本提交/回滚、协议/参考结果和对照状态清理建立必要的自动测试，避免测试膨胀。
