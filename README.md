# OCEE — 开放式演化赛博生态世界

**规范基线：v0.2.0 · 工程：P1/P2/P3 + S0–S20 开发基线，CI 93 项通过 · E001 尚未校准、未预注册**

OCEE 是与 CIOC/CL 系列**相互独立**的研究路线。其长期目标是探索一种能够适应未知数字环境、学习使用现有软硬件与网络服务、创造新工具并持续改进自身的赛博生命培养机制。

首个原型 **OCEE-0** 不宣称创造出生命，也不将一般编程智能体得分等同于开放式演化。它先检验一个可证伪命题：

> 带有明确声明的通用初始能力的个体，能否在可重放的陌生协议环境中，自行产生并保存此前不具备的可复用程序能力，并将其迁移到结构不同的新环境？

## 首个实验与主体类型

**E001 — 未知计算资源的自主发现与利用**

- Node A：个体的本地计算/存储环境。
- Node B：额外的受限远程计算/存储资源，不允许直连。
- Node C：未知编码的消息服务入口，按可学的有限协议家族解析并访问 B。
- **S 型（Seeded）**：人工赋予一般性探索、候选生成、可见反馈选择和经验记录能力；四组 A/B/C/D 比较固定、随机、短期适应、跨 episode 累积。
- **O 型（Origin）**：不预设高阶探索目标，单独研究探索驱动力是否形成；不与 S 的主实验效应混合统计。

即使 E001 成功，也只是支持在给定先验与环境下的一类可积累适应机制，**不代表已经证明数字生命、意识或无限开放式演化**。

## 从工程开工到科学结论：三个不同闸门

| 闸门 | 当前状态 | 通过含义 |
|---|---|---|
| **G0 Engineering GO** | **已达到** | 执行语义与工程接口足以启动内核、VM、服务实现 |
| **G1 Calibration GO** | 未达到 | 代码实际通过核心行为测试，初始程序/独立求解器就绪，可开始 E001 开发集校准 |
| **G2 Confirmatory GO** | 未达到 | 校准通过、正式 seed 封存、门槛和统计脚本冻结且预注册，才可以运行确认性实验 |

建议的最小实施顺序：

1. 实现 Rust 确定性世界内核、快照和日志（仅保留关键不变量测试）。
2. 实现受限类型化 VM、自我修改与版本存储。
3. 实现 A/B/C 模拟节点、P0/P1/P2 协议向量和 FOLD32 独立参考实现。
4. 构建 S 初始程序和四组机制开关、O 的独立基线；生成并审计不可变能力 manifest。
5. 运行独立可学性校准（开发 seed），评估资源权衡与统计功效。
6. 根据校准结果版本化修订必要参数；冻结正式配置，运行 E001 并保留包括失败在内的所有结果。

## 基本安全与科学诚信约束

- 不访问公网、真实生产系统、宿主文件或实体执行器。以后要接入真实软件必须建立单独授权网关。
- 世界内核/外部评价器/安全边界不允许被个体写入或自我修改。
- 不强制生物式繁殖、寿命或“生命值”；资源耗尽意味着动作受阻，不等于死亡。
- 仅当工具经过功能复验和来源审计，才可能计为新能力；复杂代码、变异次数和高分本身不足以证明演化。
- 环境校准样本与正式样本必须隔离；禁止失败后修改正式门槛并继续把结果称为同一次确认性实验。
- 只为确定性、权限、计费、版本提交/回滚、协议/参考结果和对照状态清理建立必要的自动测试，避免测试膨胀。
