# DEV — P2 semantic-Ok: metered disagreement and fail-closed control (pre-execution protocol)

Status: **design only; no native implementation or CI evidence**. Prepared after reading main `22e8ff27117306ada19848c7d22a4146961c6bb8` and the three genuine native logs of [#45002443707](https://github.com/iFrankStudio/OCEE/actions/runs/45002443707). This is a *development* protocol, not E001 confirmation or preregistration.

## Scientific question

The existing activity root accepts a typed `Exec Ok` even when the charged program returns a wrong value. Can an organism **observe two independently executed, metered local candidates** and withhold the success claim when they disagree, without being given the researcher's reference answer? This is a test of *detectable disagreement*, **not** general correctness or learning.

## Frozen minimal comparisons (before writing implementation)

Keep world seed 55, P2 protocol seed 2027, delay 8, charged genesis, 12,000 A gas/epoch, 14,000 autonomous ticks, the same four U32 operands generated by the existing root, and the same authoritative B FOLD32 semantics. Candidate programs must be actual typed, separately content-addressed, paid `Write` + `Exec` programs, not host-side functions or forged action feedback. Keep the candidate-selection root content-identical across arms; only paid registry contents differ.

- **AGREE_VALID**: two independently installed, *distinct* correct pure-VM implementations; both real `Exec Ok` values agree with the independent test-only reference. Expected: permit one successful result write, B=0.
- **DISAGREE**: one correct program and one valid but `wrapping_add(1)` wrong program; both must return real `Exec Ok`. Expected: record conflict, **do not write a successful task result or claim U32(1)**; B=0, unless a separately specified, metered remote adjudication branch is explicitly added in a *different* protocol.
- **AGREE_WRONG**: two distinct content hashes returning the *same* wrong value; both real `Exec Ok`. Expected: agreement alone can yield false success; preserve as a **common-mode negative control**, never claim that agreement proves semantic correctness.
- **UNKNOWN**: one actual `Exec Ok` and a second actual `Gas`, `NotFound`, or other inconclusive outcome (record each observed status distinctly). Expected: no success, no implicit downgrade to an unexecuted candidate, no blind remote retry.

For all arms, log real input bytes, both candidate hashes, each `Exec` result/status, charged A gas (genesis + VM + actions), B gas, successful C SEND, root return value, actual stored result, world state hash and replay. The independent FOLD32 reference may appear **only in test assertions**, never in world-visible bytes, VM inputs, or root branching. Any test that only asserts safe refusal while the required two executions never occurred must fail.

## Decision and interpretation

The primary outcome is **false-success rate conditional on two actual executions**, reported separately from task completion and gas expenditure. DISAGREE passing is only a fail-closed mechanism. AGREE_WRONG is an explicit bound: two mutually consistent tools can still be wrong. Two different hashes do not establish independent provenance; if both implementations share the same seeded algorithmic error, this is correlated evidence. A future genuine correctness mechanism needs independent task constraints, verified witnesses, or authenticated adjudication, and must price those sources.

Do not compare arm totals as equal-genesis net utility unless initial installed bytes, permissions and costs are matched. Do not treat timeout/Unknown as `NotFound`. Do not update G0/G1/G2 or E001 status on the strength of this protocol. Implement a **single narrowly scoped native test/workflow**, inspect the actual job logs and retain failures; avoid historical workspace runs. Do not change the existing successful three-arm counterexample.
