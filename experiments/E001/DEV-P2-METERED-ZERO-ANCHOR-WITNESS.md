# DEV — 本地可检验零输入见证：跨实现共错的独立约束

状态：**执行前冻结的开发实验协议，尚无对应原生CI结果**。本实验承接 [双工具分歧研究](./DEV-P2-METERED-DISAGREEMENT-PROTOCOL.md) 的原生 4/4 结果，以及 [#45019867266](https://github.com/iFrankStudio/OCEE/actions/runs/45019867266) 的共错阴性对照。不是正式E001预注册，也不更改科学G0/G1/G2闸门。

## 固定问题与独立证据

前次两个独立实现的VM纯程序虽然 hash 不同，却都可返回相同错误结果并骗过一致性检查。此次要求个体在**两个实付Exec已对同一个实际任务输入返回完全一致的值之后**，使用一项由公共FOLD32规则直接推导、但并非给定该任务答案的零输入约束：

`FOLD32([0,0,0,0]) = 0`

活动根必须通过真实、收取A gas的 `WorldCall::Exec` 调用候选程序对 **16个零字节** 计算，读取实际 `Code::Ok` 与真实 `Value::U32(0)`，才可把先前一致的真实任务输出写入成功工件。零约束是研究者明确提供的任务先验，而非个体独立发现的数学性质；世界不新增真值oracle、测试宿主不注入目标输出。失败则 fail-closed，**不能**在未经额外授权的情况下调用B或C。两个一致结果的双Exec链不能省略。

这项见证只检验**一个校准点**；它不具有一般语义正确性保证。为了避免把「能识别恒定+1错误」错称全面可靠，必须同时保留一种「全零正确、实际输入错误」的对抗性程序（两份实现分别计算原算法后额外`Add(value,value)`，即把非零正确输出乘二）。这样两个工具彼此一致、零样本也通过，却都在实际任务上错误，仍可能出现假成功。

## 执行前冻结的四臂预测和判据

world seed55、P2已见开发seed2027、delay8、A12000 gas/epoch、14k自主tick、公共P1学习、相同实际四U32真实任务不变。四臂活动root内容 hash 必须完全一致；工具依然是研究者有偿安装且内容寻址，候选hash通过普通有偿注册表Write存入，不在根内由宿主代选路由。所有结果要独立审计实际 `Action::Exec` 的程序hash、真实输入、代码、输出与A计费；维持原始B/C协议但没有任何隐式B回退。

| 条件 | 两次真实任务Exec | 额外零输入Exec | 根应如何处理 |
|---|---|---|---|
| VALID | 两个不同程序都返回正确值 | 至少原主程序真实Exec Ok且返回U32(0) | 成功，写正确结果 |
| COMMON_PLUS_ONE | 两个不同程序都返回真值+1 | 原主程序零输入真实Exec Ok却返回U32(1) | 拒绝成功，结果工件不存在 |
| COMMON_DOUBLE | 两个不同程序都返回真值*2模2^32 | 原主程序零输入真实Exec Ok且返回U32(0) | **假成功仍存在**，必须以绿色负对照实证说明单点见证不充分 |
| DISAGREE | 主程序正确，第二程序返回真值+1 | 两份已冲突，零见证分支不得执行 | 拒绝成功，结果工件不存在 |

所有程序都必须通过Program.validate、真实收费Write安装并由隔离VM执行；任何原生Run失败都必须留痕，不事后调种子、提高预算或延长窗口掩饰。记录计费genesis、VM gas、世界动作A gas、零输入验证费用（含真实完整Exec gas）、B gas、C SEND、返回值、落盘值、真实任务正确值（**只能在测试assert中**）、快照重放与越权动作。若因首epoch实际Gas不足而出现失败，应先记录真实Action反馈，区分资源不足和可执行性缺失，不将红灯改为「科研成功」。

## 解释边界

两次算法一致 + 一个零输入锚点的机制是研究者预置的有限证据门槛。它只检验一种公开约束下的局部反例，并不能证明两个程序独立、普遍正确或有自发发现、跨episode信任记忆。任何比较跨臂A总成本都须披露各臂初始安装bytes与真实费用不同，不能直接认定等起点净效用。G0 GO、G1/G2 NO-GO；正式E001仍未校准与预注册。

### 可证伪结论与局限

1. **实际可检测的共错**：COMMON_PLUS_ONE的两个不同程序均把正确任务值增1而达成一致，单凭双执行无法识别；活动根却额外收取167 A gas让主工具计算零输入，真实输出1违反已知零约束，故根返回U32(0)、没有写入成功工件。证明这个**固定已知约束**能拦截一类以前漏掉的共同偏差。
2. **真实不能检测的共错**：COMMON_DOUBLE的两个不同程序都把原正确输出加倍；零输入时倍增依然为0，活动根对这个样本的有限验证通过并将错误值2830358934保存，仍宣称U32(1)。不同算法、相同错误和一个满足的约束仍不能证明真值；该负例必须保留。
3. **成功不损失**：VALID两个不同纯VM程序真正确输出且零见证真U32(0)，最终活动根正确持久化1415179467；DISAGREE原输入两值不等，且**没有启动额外零见证**，立即fail-closed，不消耗B。
4. **资源**：新增见证需第三次独立真实Exec（165–167世界gas），还需要活动VM执行和若干付费Read，所以不能把165–167当全部附加开销。各臂工具代码、genesis成本不同，不能跨臂扣减总A作为等起点净收益。前期双工具baseline也使用不同根与收费，横比只能粗略描述。
5. **证据层级**：零等式是研究者预先写入根的公共任务性质，**不是个体自行发现或独立受信第三方证明**；这项单点校准不能识别保持零性质的共享错误，不能对一般输入给出可靠性保证。仍需研究独立的、合法付费的任务特定见证或可验证证书及跨任务适应性；正式E001并未校准或预注册。
