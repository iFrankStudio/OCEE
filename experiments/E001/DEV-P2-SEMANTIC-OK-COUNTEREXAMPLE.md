## 为什么现在验证

原生 [#44998219987](https://github.com/iFrankStudio/OCEE/actions/runs/44998219987) 证明：活动 VM 能区分本地 `Exec Ok` 与 `NotFound`，仅后者触发真实远程 B24。**但 `Ok` 是执行成功，不是算法正确性证明**。当前根在 `Ok` 后直接保存结果；一个可执行但语义错误的本地工具可能导致“形式成功、任务错误”。这是对“利用环境反馈作可靠适应”更强、信息增益高于重复可用性测试的最小反例。

## 冻结对照与预测（执行前）

沿用已验证的开发世界 seed55、P2 seed2027、delay8、真实 12000 A gas/epoch、14k tick、收费装载、共同根程序和相同16字节输入。不得更换任务值、延长预算、事后剔除失败或把 `Unknown` 当作未执行。

| 条件 | 本地工具真实执行行为 | 现有根的预期路由 | 科学判据 |
|---|---|---|---|
| VALID | 原通用本地 FOLD32，返回正确 U32 | `Exec Ok` → 本地 | 正确结果、B0、C0 |
| ABSENT | 目标程序 hash 未安装 | `Exec NotFound` → 远端 | 正确结果、B24一次、受信 ACK/RESULT |
| CORRUPT | **有偿安装**且静态验证通过的纯VM程序，按同输入稳定返回错误 U32，`Exec` 状态为 `Ok` | `Exec Ok` → 本地，不会因语义错误回退 | 若根仍报告成功而结果错误，即构成语义盲点反例 |

CORRUPT 应只在原本 `FOLD32` 的结果构造处引入确定性、非零差异，保持输出类型、长度、可执行性和资源计费；不得以 `InvalidProgram`、`Gas`、`NotFound` 或宿主伪造 `Ok` 替代真正错误的 `Exec Ok`。记录真实程序 hash、输入、独立正确结果、工具返回结果、活动根保存值、最终 U32 状态、A/B/C 账本及快照一致性。

## 反证逻辑和下一步闸门

如果 CORRUPT 真正执行并返回 `Ok`，但结果错误且根依然保存成功，则只能得出：**当前研究者预置的可用性路由缺少语义验证**。这不证明生命体“学习失败”，因为根从未获得足够的正确性反馈。若 CORRUPT 被拒绝或未执行，记录为其他机制结果，不能充当此反例。若结果正确，则首先检查变异是否真的改变算法，而非宣布自主修复。

任何后续修复必须先明确个体可合法获得的独立正确性证据（例如付费冗余求解、可检验任务约束或带因果身份的外部反馈），再比较增加的 A/B/C 成本与错误率；不能由测试宿主直接告诉活动根正确答案。随后才考虑跨 episode 的可持久经验及写入/读取消融。未经实际原生运行，以上均是**预测**，不调整 G0/G1/G2 和 E001 闸门；以最新工程检查点为准。

### 解释与边界

这里的**实质性阴性结果**是：执行成功不意味着计算语义正确，当前活动根缺少独立的任务正确性证据而产生可复现的假成功。宿主参考 fold32 **仅用于测试审计和assert**，没有通过新的世界API或隐藏状态交给活动VM。正确性判定所需的信息未自动出现，因此不能将错误归咎于个体没有从不可见真值中学习。成功本地工具可执行、失败但真实工具可执行，均可走同一现有固定策略；算法模板、任务理解、候选hash和验证判据全部仍有研究者先验。

三臂初始工具安装状态及真实费用不同，不是严格等起点成本比较。数据只支持现有语义风险的存在，不能从 INVALID/NOTFOUND/Gas 行为外推出任意输入皆错误，也不能把一次通过等同于开放式演化。已将一次性workflow恢复为仅 workflow_dispatch；完整workspace没有在这次研究中运行或声称通过。

### 后续新校准门槛

后续语义验收设计必须首先交代**活动 VM 自身可见且需要付费取得的独立证据**：例如两个不同程序来源的冗余计算，以及不一致时拒绝持久提交结果；或者受权限约束的任务公开见证。两个工具一致仍不能构成一般语义正确性证明，更不能把研究者预先知道的正确值偷偷写进个体状态。对于证据不足，应保持 Unknown 或拒绝任务完成，不允许将单个 Exec Ok 自动升级为任务成功。然后比较额外A gas、独立证据获取成本、跨episode持久化及语义伪装反例。
