# S17 — 无家族标签的 P0/P1/P2 有限参考求解器（开发集）

- **日期**：2026-11-18
- **实现**：[restricted_families.rs](../../crates/calibration-solver/src/restricted_families.rs)；[成对实验](../../crates/calibration-solver/tests/three_family_reference.rs)
- **已验证 CI**：[GitHub Actions #44304851025](https://github.com/iFrankStudio/OCEE/actions/runs/44304851025)，Rust workspace **77 passed / 0 failed**；三协议两项测试均通过。
- **研究性质**：独立校准程序，非 S/O 活动 VM，非 E001 正式集。

## 被验证的问题

让参考求解器**不接收协议家族标识**，只给它 `/public/C/hello` 中可见的请求/响应和普通帧反馈。它能否从预先给定的三种语法假说中选出一个，通过合法请求与响应完成真实 B 计算？

这检验**有限已知协议集合的识别和使用**，绝不等同于从任意未知字节世界中发明新的解析语法。

## 信息与机制边界

- **显式研究者先验**：P0 marker/length/XOR；P1 0x7e 定界、0x7d 转义、XOR key 可由合法帧推断；P2 五角色嵌套 TLV/XOR；112 个候选 opcode；三 u32 FOLD32 负载和合法 ACK/RESULT 响应结构；等待回复的测试传输适配器。
- **真正通过公开样例发现的内容**：匹配的三类结构假说之一、当前实例 marker/校验 key 或 P2 字段 tag 映射、HELLO opcode、远端计算与结果查询操作码、有效返回的结果。
- **从算法输入排除**：私有 `Family`、协议生成器、seed、B gas 账本、内部任务表、参考结果和每次请求的具体错误标签。所有错误诊断在适配器统一为 `Other`，合法响应帧保持可见；计费仅由测试外部读取。
- `ocee-calibration-solver` 的生产依赖仍为空。权威的协议模拟器和世界内核只存在于开发测试中。

## 正常成功路径与对照

统一求解器从公开 HELLO 请求/响应尝试三种静态假说，要求**恰好一个**符合字节语法和配对要求；采用 S16 的合法 FOLD32 请求探测与 ACK/RESULT 响应识别。协议级 **P0/P1/P2×6 个公开 seed = 18 个案例**成功，世界级 **P0/P1/P2×seed 7、42 = 6 个案例**通过正常 A→C→B 延迟消息链。世界测试核验 A 配额 12,000 gas/epoch、B 计费恰好 20 gas、独立 FOLD32 结果和快照确定性。

**修复错误能力归因**：以前的 `crates/protocol-sim/tests/restricted_probe.rs` 在参考发现函数内部检查 `b_gas_charged>0`，这个只对研究者开放的字段不是普通服务帧，故其“信息受限”的结论证据有特权信息泄漏。已删除这一旧测试，使用独立 crate 的纯公开帧判断替换；研究结论以本 S17 为准。

## 明确不能推出的结论

1. 不证明在第四种未列明语法上仍能成功；失败反而是其有限假说空间的预期行为。
2. 不证明初始 S/O VM 具有这套解码策略；其算力时间由研究端 Rust 主机执行，**未计入个体 VM gas**。世界动作、链路和 B 计算虽然按系统规则计费，但不能将这一预算等同于真实 VM 执行相同算法的成本。
3. 不证明个体主动选择跨家族迁移或积累了跨 episode 的程序能力；没有新程序创建、初始 manifest 冻结、正式对照组或预注册。
4. 下一重要研究闸门应让**同一受限活动 S VM** 经公开可见反馈构造/组合新的协议工具，核验代码来源、实际 VM gas、负迁移与 A/B/C/D 对照；不得将参考求解器当作零成本的内置 helper。

**研究状态：G0 GO；G1/G2 NO-GO；全部是开发集可学性下界证据。**
