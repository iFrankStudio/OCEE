# E001 前置开发研究：S2 利用远程资源并获取结果

- 日期：2026-11-17
- 状态：**Development Evidence ONLY**；**不是** E001 正式实验，也**没有**达到 M0
- 验证代码：[S2-P0](../../crates/organism-seeds/src/s2_p0.rs)、[端到端测试](../../crates/organism-seeds/tests/s2_remote.rs)
- 已验证 CI：[GitHub Actions #44070090727](https://github.com/iFrankStudio/OCEE/actions/runs/44070090727)，Rust workspace **28 passed / 0 failed**

## 待验证假说

在已知 P0 家族帧规则、已预置通用字节处理与反馈驱动搜索策略的情况下，个体能否：

1. 读取 S1 在过去获得的未知 REMOTE_EVAL 操作码，而不是由外部测试直接注入正确取值；
2. 读取不含正确答案的公开 FOLD32 工作项，组装正确的远程计算请求；
3. 通过 C 请求 B 执行任务，消耗 B 计算配额，并接收成功受理反馈；
4. 再通过环境交互发现 RESULT 操作码，读取并保存正确的 32 位计算结果？

这是单协议家族内的**有限参数探索与远程资源利用**，不是陌生协议的通用发现能力。

## 实验实施与区分来源

- 环境：Node A（个体 VM）、C（P0 XOR 编码服务）、B（有界 FOLD32）。
- 研究者设定：**S1 和 S2 均为预先编写的 VM 程序**。研究者先安装 S1，S1 自行搜索、保存 REMOTE_EVAL 候选；S1 执行结束后，研究者将 S2 保存为新版本并通过 CAS 切换活动程序。
- **S2 的能力先验**：P0 结构、XOR 校验计算、固定 3 个 u32 的工作项格式、结果状态字段、结果长度、opcode 有界搜索范围、固定消息等待方式。上述均不属于本次新涌现知识。
- **S2 未获预置的信息**：真实 REMOTE_EVAL 和 RESULT 操作码值、隐藏协议种子、工作项的具体 u32 数值与正确计算结果。
- 工作项公开路径：`/public/E001/job0`，包含 `job_id`、`count`、`values`、`values_le`、输出约定；**不包含 B 返回的正确答案**。
- S2 将结果分别记录于 `/self/results/job0/ack` 与 `/self/results/job0/value_le`；两种存储写入均来自它自己的世界 `WRITE` 操作。

## 已验证结果

| 开发协议 seed | 工作项 | VM 发现并提交 REMOTE_EVAL | B 执行 | VM 发现 RESULT 并保存计算值 |
|---|---|---|---|---|
| 7 | 3 个由 world seed 产生的 u32 | 通过 | 20 B gas | 通过 |
| 42 | 3 个由 world seed 产生的 u32 | 通过 | 20 B gas | 通过 |

上述每次执行的工作项具体数值随 seed 改变。测试使用一份独立的计算表达式检查 `value_le` 是否与 FOLD32 的预期值相同；检查结果不是个体的学习反馈。

世界也验证了持久化对象、实际计费、程序版本变化与快照恢复。

### 失败诊断与修复

开发中曾出现 S2 能发现 RESULT 操作码，却一直无法取得结果。CI 因果轨迹显示 RESULT 请求包含了不应存在的 FOLD32 负载，被 C 以 `BadBody` 拒绝。原因是程序跨块传递错误，将**完整 REMOTE_EVAL 请求**当作 RESULT 的空负载构造模板。改为保留 S1 原始空负载候选后，完整验证通过。这一失败与修复保留在 Git 历史中。

## 不得越界解释

- S2 是研究者安装的预定义策略，**没有自主创造新的程序或工具**；`/self/results` 仅为运行记录，不是新工具。
- 只验证 P0，同家族参数变化；没有验证 P1/P2 的结构性未知，也没有环境迁移或跨 episode 累积。
- 开发测试使用 `100_000` A gas/epoch、固定 3 个 u32 的任务，尚未校准 E001 标准资源预算和长期收益。
- 两个 seed 不是统计推断样本；没有正式预注册、盲测、A/B/C/D 对照和真实工具生成机制。
- **E001 G1 和 G2 仍为 NO-GO。**

## 下一研究目标
