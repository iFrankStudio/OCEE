## 要求与可证伪观察

S24 已确认 P2 seed99、C 消息延迟6 tick 时，受计费 VM 真正经历三阶段 `RECEIVE=Empty` 合计156次、仍取得真实 B/FOLD32 结果。此前 S24 的 `World::from_snapshot` 检查发生在任务完成后，**并不能证明大量 Empty 后尚未完成的 VM continuation、其循环计数、邮箱/待交付消息及资源账本可以在重新加载后继续工作**。

S25 不改变原 S22/S24 初始个体、不添加新指令或研究者任务答案注入，使用原相同 Rust 程序哈希与 `Config{seed:99,message_delay:6,a_gas_per_epoch:12_000}`；只增加一个**必要的持久性不变量检查**，另给它一条独立定向 CI。

[测试源码](../../crates/organism-seeds/tests/s25_p2_restart.rs)，[CI 定义](../../.github/workflows/s25-restart.yml)。

实际测试步骤：通过世界正常 WRITE 安装受限 VM，正常 `tick_autonomous`，直到 VM 观察的三个 RepeatBounded loop counter 合计 **大于128、任务仍未完成**；此时从现有世界快照 JSON 重建第二世界，不清空 continuation、pending C transport、消息队列、资源配额和审计记录。断言快照前后状态哈希、step、三个 loop counter、A 累计 gas、B 计费相同。让“原世界”与“重建世界”分别继续真实世界调度，直到各自完成，再**逐条比较完整世界 audit**和最终世界状态哈希、独立 FOLD32 工作结果、三段有界计数，以及 B 只计费20且不被重启重复执行。

**研究端可以选择何时截取快照**；活动个体没有自己调度快照或创造恢复算法。这是 VM/世界内核确定性持久化证据，不是生物式自愈或内源开放式演化。

## 限制及研究下一重点

1. 这里只测试**一个**特定 seed、延迟等级、快照点及同一个运行进程中的 JSON 序列化/反序列化；没有验证 SQLite 崩溃原子性、跨内核版本/硬件恢复、磁盘损坏、真实网络服务或多个任务并发。
2. S24 的有限重试、容错策略、TLV 格式和 B 任务协议全部由研究者提供。S25 证明的是在真实异常负载下**连续执行状态与计费不丢失**，没有新的主动策略选择、工具发明、开放式演化。
3. 下一阶段应从不断研究者手写新初始程序，转向**同一已冻结初始个体的能力选择、候选构造、验证、版本提交和跨 episode 净收益**；否则再多重启测试也不能推进 G1。正式 S/O、四组机制对照、独立确认集与预注册仍缺失。**G0 GO，G1/G2 NO-GO。**
