# DEV S29 — Paid zero-yield feedback memory, one-cycle cooldown, recovery and observational lower bound (pre-registered)

**Status: protocol frozen before implementation; first native four-arm 4/4 passed and archived.** Baseline main `432fd9fba0111d5f000699d1a0bf786bfbd3338a`; preceding [paid resource gate study](./DEV-S29-RESOURCE-BUDGET-TRIGGER-PROTOCOL.md) verified 5/5 after a retained 4/5 fixture failure, including a **real 2,945 A / 0 B** high-pressure all-protected episode (fixed gate 4096B and 3000A). This is a researcher-supplied finite policy study, **not** a new kernel or VM capability, a hidden oracle, or spontaneous self-generated goals.

## Hypothesis and generalization boundary

It is impossible for a purely resource+version-catalog based detector to correctly distinguish all fully protected and partially reclaimable worlds when the two worlds have the same owned-version set, object sizes, storage used, A budget, and the *only differing information* is equal-length raw reference bytes in ordinary self objects. Therefore the main practical hypothesis is weaker: **once an individual has paid to discover a zero-yield episode, persisting negative feedback and skipping one later attempt reduces repeated wasted A, but may delay discovery when the environment changes**. A subsequent bounded retry may detect new opportunities. No secret GC eligibility list, free reference status, or special action is given to the VM.

## Fixed researcher-authored policy and cost contract

Start from the **same** existing `resource_budget_catalog_root` and exact `Read("/sys/resource-status")` gate (free capacity <4096B; available A >=3000). Maintain the existing `Read("/sys/self-version-catalog/0")`, one real charged `IndexVersionRefs`, bounded 8-try `ReclaimIndexedVersion`, matching feedback guards. Wrap this graph with a new verifier-approved **`RepeatBounded(limit=3)`** loop, one initial researcher activation only, and real VM `WorldCall::Read/Write` to `/sys/self-object/maintenance/s29-dry-run` and `/self/maintenance/s29-dry-run`:

- On no stored memory: run usual resource-gated bounded discovery. After **all 8 real candidate attempts return Conflict/NotFound and zero GC successes**, record `b"1"` at its own key with **real paid CAS** (None for creation) and only then `Observe` (paid) before next round. Unrecognized/error feedback **must fail closed** and not fabricate a dry-run mark.
- On reading stored `b"1"` via **real paid versioned metadata**: attempt an atomic CAS from `b"1"` to `b"0"` with exactly the version read, then skip this round's resource/catalog/index/GC work. One paid Observe advances to next round. If the CAS lost a race, abort instead of changing memory or running GC. The skip is an intentional, finite **one-round cooldown**, not indefinite suppression.
- On reading stored `b"0"`: run the original paid resource gate + bounded discovery again. On success (real GC) return U32(1), leaving memory at `b"0"`; on another zero-yield episode re-read current metadata (do **not** assume version 0) and paid CAS to `b"1"`, then finish after RepeatBounded3. The final U32(0) indicates no successful GC, not proof of no future opportunity.
- The sole researcher-supplied policy graph is exactly the same across research worlds, with **no candidate 64-byte hash literal**, no hidden in-kernel risk field, no new WorldCall/opcode, no new privilege, no direct access to `World.version_ref_index` by the VM. CAS/Observe/memory metadata, VM instructions and all-world actions must be real, A-priced and in audit. Cycle counters and source memory persist in deterministic snapshots. Test setup may construct true paid version refs, control event timing, fork snapshots, and inspect internal state **only as researcher validation**.

## Four preregistered native controls

1. **PAIRED_INDISTINGUISHABILITY**: start the same actual S29 repaired P2 world129/protocol42 and same researcher-paid three 834B old candidate versions + one installed research maintenance root. Fork a snapshot and pay to create exactly the same number and 64B lengths of ordinary own pin objects in each world: in **PINNED**, each holds the installed version's actual 64B lowercase hash, in **OPAQUE**, each holds non-hash filler of the same length. Both must yield byte-for-byte identical and identically priced real `Read("/sys/resource-status")` and `Read("/sys/self-version-catalog/0")`, with equal object count, capacity, used and A. Nevertheless a subsequently **truly paid** certificate+reclaim must correctly return Conflict in PINN and Ok (release >0 bytes) in OPAQUE for the *same researcher-chosen known old candidate*. This is limited to those two observation interfaces; it does **not** prove no other attainable low-cost observation could distinguish worlds.
2. **DRY_REPEAT**: actual same P2 S29 background B20, all *genuinely installed* versions researcher-paid pinned (not just 3), free space initially 2048B minus true pins, A healthy. One researcher activation, one bounded VM over three rounds: full catalog/index/8 GC Conflict and one paid b"1" CAS; second round true versioned metadata read→paid b"0" CAS→**no catalog/index/GC**; third round independently pays index and 8 Conflict before writing b"1" again. Expected two complete scans (not three), 16 conflicts, zero freed B, memory value b"1" at monotonic version2, no root reactivation, complete deterministic snapshot replay. Audit the isolated second-round A fee and subtract from first real full-scan episode (do not mix VM and action accounting units, and do not treat B as A).
3. **RELEASE_AFTER_COOLDOWN**: same initial truly all-protected P2 world and identical root; after seeing real VM second-round b"0" CAS and before third round catalog/index, **researcher** pays a real CAS updating precisely one ordinary 64B pin to same-length filler; index invalidates conservatively. Third iteration must genuinely rebuild index and successfully GC a now-unpinned version (>0B) from a hash obtained from the actual charged catalog, leaving other pinned programs installed; final return U32(1), no false veto. A delayed retry is permitted but must be labeled an intentional missed opportunity during cooldown, not instantaneous change detection.
4. **STALE_MEMORY_CAS**: same pinned world; after real first dry-run mark and after second real versioned memory read returned version0, but before the VM's actual reset-Write, researcher issues real paid CAS setting the memory to b"0" and advancing its version. The VM's stale version0 reset must get **Conflict/0A**, abort without any second full index or GC, preserve latest memory contents/version and snapshot correctness. Never treat stale CAS as a successful cooldown write.

Controls run on independent Ubuntu-native Rust jobs with tight `cargo test -p ocee-organism-seeds --test s29_reclaim_version s29_dry_run_memory_native -- --ignored --show-output` and `OCEE_S29_DRY_ARM`. Only the specialized workflow's temporary push trigger triggers once; restore to workflow_dispatch after verification. Preserve any red run and pre-register fixture-only repairs before implementation. No 1000-seed efficacy claim, no comprehensive workspace run unless actually executed.

**Scientific gate remains G0 GO / G1,G2 NO-GO; formal E001 remains uncalibrated and not preregistered.** This experiment can confirm a bounded feedback **memory/cooldown** mechanism, not information-theoretic optimality, endogenous objective discovery, free clean-up predictions, or open-ended cyber life.

### Limits and next decision

- The policy is **researcher-authored and researcher-activated once**. The previous and current versions of the 3-round finite policy do not autonomously decide to start new lifetime episodes, choose the risk threshold from fitness, create a maintenance objective, discover compressed or external references, or perform open-ended evolution. The individual did execute real `WorldCall::Read/Write/Observe/IndexVersionRefs/ReclaimIndexedVersion` and paid its compute/storage costs. The researcher-created all-pinned scenario and reference release are explicitly **external tests**, not autonomous agent choices.
- On **RELEASE_AFTER_COOLDOWN**, a newly available reclamation opportunity is intentionally **missed during the cooldown round** and recovered only in a subsequent round. Zero-yield memory is an informed prior about recent outcomes, not oracle truth; indefinite cooldown would harm adaptability.
- New own memory `/self/maintenance/s29-dry-run` is a paid object (1B value), version0→1→2 under actual CAS when failed twice. It can race and must not silently overwrite a newer value; `STALE_MEMORY_CAS` tested a real costed concurrent-writer collision. Other VM faults fail closed. All long arms retain true previous P2 task B=20, original active registration data and deterministic full snapshot replay; test suite is targeted four jobs, **not** a fresh entire Rust workspace result.
- The first-round full-scan ~1680 A remains unavoidable in this *particular* policy because it still needs real certified references. The new learned bit only prevents unnecessary **repeats**; detecting genuinely novel zero-yield situations before the first scan would require additional information, not a pretend free status flag. This is a finite feedback-based resource-reaction mechanism, not a net resource/fitness theorem.
