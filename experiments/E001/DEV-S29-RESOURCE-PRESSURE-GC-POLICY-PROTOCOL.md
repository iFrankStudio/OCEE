# DEV — 活动VM读取真实资源后决定是否进行批次GC（执行前冻结）

**状态：实验方案先于代码冻结，尚无此轮原生实验结果。** main 基线 `9c2ef0688fc8a608806f7d20f71da9160c9f40e5`。继 [可信引用证书首次成功4/4](./DEV-S29-CERTIFIED-REF-INDEX-PROTOCOL.md) 的三版本同快照GC动作节省3263 A，但不能称净效益，本研究检验“世界资源状态改变时，**同一个有限活动VM**能否选择回收/不回收”，而非研究者在两条路径的测试脚本中代替它做选择。

## 冻结输入、界限与新观察面

原世界 `Observe` 只反馈`step/A_gas_available/A_storage_capacity/public_sample`，不提供actor真实`storage_used`。唯一必要新接口是研究者明确授予的**元资源观察能力** `Read("/sys/resource-status")`，复用原`WorldCall::Read`/世界`Action::Read`，无新的宿主动作类。仅对合法actor允许，按真实当前世界响应UTF-8 JSON `{"used":U32,"capacity":U32,"a_available":U32}`，不得包含对象key、任务隐藏真值、未公开版本、候选可达性、下阶段结果或全局私有存储。成本固定**2 A**（先扣再反馈当前剩余A），`u32`溢出时`Quota`并不返回截断伪信息。不能让VM在纯隔离Exec中免费读（既有isolated READ ACL仅限self和原公共hello）。此是对正式E001原六原语环境的**新增可见信息**，后续需独立版本化、校准与对照，不能直接归功于生物式自主性。

所有完整世界P2采用world seed129、protocol seed42、A12k/epoch、最长期望16,384 ticks，S29源根真实一次原子修复正确→B20、heldout5、正确FOLD32结果。研究者**只在完成真实任务后**有偿放入三个合法、尚无活引用的不可变程序（与上一个同快照研究相同：279/276/279字节）、再真实收费读取`/sys/active-version`和CAS启动一个固定的政策维护根。这一研究者切换阶段不是个体自身产生生存目标。空间容量与当前epoch A预算条件由实验环境明确操控，并保存于世界snapshot和审计；不把它们写成个体自己改变外界资源。

## 冻结单一静态活动VM策略（四臂同一root hash）

- 首先经普通世界`Read("/sys/resource-status")`真实付费获取自身`used/capacity/a_available`，验证`Code::Ok`后以VM通用JsonFieldU32、Sub、Div、EqU32和有界Branch计算：
  - 空闲 `free=capacity-used`；`quarter=floor(capacity/4)`（测试容量≥4）；
  - **pressure**：`floor(free/quarter)==0`，即测试中空闲严格小于约25%；`capacity`不能小于`used`；
  - **budget**：`floor(a_available/2200)!=0`，即剩余A至少**2200**；2200是研究者根据上一真实索引扫描1667 A加有限VM余量选择的保守阈值，**并非证明适用其他世界**；
  - 本轮候选恰3份，都是研究者预先给定的合法版本hash，不向VM泄露任何隐藏评价结果。两条件都满足，才有权执行`IndexVersionRefs()`一次，然后最多三个有偿`ReclaimIndexedVersion(hash)`；如果索引/任一回收Action并未得到真实`Code::Ok`，单向图失败返回U32(0)，绝不盲目继续/复试。成功完成三次回收返回U32(1)；未满足资源条件返回U32(0)，并应完全没有索引/GC Action。**没有无界循环**、没有隐性oracle、没有猜测注册表可达性。
- 活动根本身相同；其已知候选数和压力/预算阈值均由研究者事先提供，个体只能在这些约束内做**运行时资源条件分支**，不等于算法/目标/阈值内生演化。
- 世界内核已拥有的索引失效屏障、原始64字节ASCII活引用检查与纯EXEC副作用限制不放宽。不改`IndexVersionRefs`或`ReclaimIndexedVersion`费用模型，不降低失败收费，也不增加A或B配额。研究者制定的根需要付费维护自身程序版本。

## 预冻结四臂与失败判据

1. **PRESSURE**：真实S29任务完成、准备三待回收工具并有偿启用同一维护根之后，研究者将node A存储容量设置为严格大于`storage_used`但空闲小于25%、当期A剩余充裕；必须记录真实`Read /sys/resource-status`返回值；活动VM基于实际字段作肯定分支，亲自执行1次索引+3次真实GC、释放**834B**、B20不重复、新Len仍有效、活动返回U32(1)、快照一致，并记录资源成本。
2. **RELAXED**：同一个根/同样3份有偿程序与S29完成条件，但研究者设定真实容量为`storage_used*2`（空闲50%）、A充裕；**真实元资源Read后自行拒绝GC**，Index/Reclaim均0次，版本与存储均保持、B20不重复、U32(0)，成本只有观察与判定VM费用。
3. **LOW_GAS**：同样存储压力，但研究者在维护活动启动前使当期A资源为`1500`（小于2200，足以完成一次读取和有界分支），当前tick不跨epoch自动充值；实际Read成功后自行拒绝GC，无Index/GC/删除，世界资源/快照一致、U32(0)，不得使用`Code::Gas`盲试安全GC。
4. **INVALIDATED**：与PRESSURE同样正决策，活动VM成功付费索引后，在下一次回收动作之前研究者经**真实世界CAS Write**在`/self/pins`写下首目标hash并使证书失效；重启活动VM执行下一步时首次快速GC真实`Conflict`、无该旧版本删除、后续两GC均0次，返回U32(0)。这是**异步环境插入**，并不证明同一个体主动识别了所有竞态；失败关闭、无危险重试即为通过。

只进行定向Rust CI。需要审计每臂程序hash、元资源Read真实反馈/收费、索引+GC回执序列、是否产生自发GC/跳过、存储差、实际B与P2任务产出、VM/Action A费用及快照恢复一致。**不比较不同容量初态的完整A成本为等起点因果效益**；跨臂仅能说明同一固定根根据自身可见环境作不同分支。若原生失败，保留完整红例/修复链；最终工作流恢复workflow_dispatch。

## 科学限制

相较过去“研究者指定回收”，此实验的行为分支若成功是更弱但真实的**资源感知条件性自我维护**：研究者仍给定维护根、候选及两阈值，也直接选择是否进入维护阶段；不能声称该生命形成内生维护目标，不能推断真实网络分布式GC安全，不能宣布G1/G2达标。正式E001未预注册/校准，**G0 GO、G1/G2 NO-GO**。
