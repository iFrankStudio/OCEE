## 本研究提出的更窄问题

是否能够取消 S1→S2 的人工程序安装，让同一个活动 VM 程序在已知 P0 帧规则的环境中，把自己发现的未知操作码转换成一个**真的可执行且输入可变**的程序版本，并在当前 episode 内试验、注册、调用这一工具？

研究还设置诊断屏蔽消融，区分依赖可见反馈还是只依赖搜索预设。

## 初始先验与实际产生物的严格区分

- **研究者预置**：S1 的 P0 XOR 分帧知识、探测范围、`BadBody` 反馈选择、通用字段/字节运算、**P0 报文生成程序的 JSON/SSA 代码片段**、程序版本哈希算法、工具注册步骤、固定 3×u32 开发工作项编码。这些代码片段已经给出了工具算法的主要结构。
- **运行时由个体获得**：从环境反馈中发现当前实例的 P0 marker 和 REMOTE_EVAL opcode 的具体取值；由它们形成的可执行工具版本哈希，及后续与 B 的具体交互结果。
- **个体通过 VM 世界动作完成**：拼接有效候选程序 JSON → 域分离 SHA-256 内容哈希 → `WRITE /self/versions/<hash>` → 带输入的隔离 `EXEC` 试验 → `WRITE /self/tools/p0-eval-frame` 注册 → `READ /public/E001/job0` → 对新工具执行 `EXEC` → 将构造帧 `SEND(C)` → `RECEIVE` 并持久化回执。
- 当前活动程序一直是初始的 S1 派生变体；工具作为 `/self/tools/*` 注册、由 VM 调用，**没有切换为新的活动程序**，也没有研究者中途替个体选中或安装某个候选。

工具的纯函数行为：输入 `request_id:u32le | count:u16le | values:u32le[]`，输出 `marker | kind=0 | learned_opcode | payload_length:u16le | payload | XOR_check`。它既没有预置隐藏操作码，也不执行外部世界操作；外部 `SEND` 只能由活动个体正常调用并按权限计费。

## CI 已验证范围

| 证据 | 环境/输入 | 结果 |
|---|---|---|
| 程序派生与注册 | P0 三个开发种子：7、42、99 | 由 VM 生成不同于初始活动程序的已验证、内容寻址工具版本 |
| 自测试及实际使用 | 同一 episode 的公开 3×u32 工作项 | 个体自己的 `EXEC`、`SEND`、`RECEIVE` 形成受理回执，B 真实消耗 20 gas |
| 输入复用 | 两个开发测试输入：1 个 u32 与 4 个 u32 | 同一工具版本在两种输入长度下构造正确报文并调用 B，分别消耗 12 / 24 B gas |
| 消融 | 相同初始先验，关闭诊断标签选择 | 没有形成并注册工具；不是 E001 的正式四组对照 |
| 确定性与状态 | Snapshot / JSON 状态 | 状态摘要和快照恢复一致 |

工具复用测试的不同输入由研究测试驱动器调用已注册工具，**不同于**同 episode 内由个体自行调用工具完成公开工作项；两个来源都在事件日志中可区分。

## 归因结论（严禁升格）

这是在给定 P0 报文生成算法模板时的一项**参数驱动的可执行程序派生与采用**。观察结果支持一个实现上重要的命题：受限世界里的活动程序能够以真实反馈修改自身持有的工具集合，并在以后复用新工具。

不能声称：
- 个体独立发明了协议解析/报文构造算法；
- 出现了事先完全不具备的语义能力（模板已包含主要算法）；
- 适应 P1/P2 的未知结构，或跨协议实例直接转移；
- 存在无人工先验的开放式演化；
- 完成标准资源模型、正式 A/B/C/D 实验、独立可学性校准或预注册。

**G1 = NO-GO，G2 = NO-GO，E001 M0 = 未达到。**
