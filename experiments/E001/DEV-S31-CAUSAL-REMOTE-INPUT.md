# OCEE S31 — 生成程序的数值首次进入真实远程任务数据流

**2026-11-20 · 开发实验，非正式 E001。G0 GO；G1/G2 NO-GO。**

## 从 S30 走向真正的任务因果路径

S28–S30 已验证个体在研究者预置的有限图语法下可以生成、运行、封存、继承与重新学习程序，但实际 B 服务 REMOTE_EVAL 请求中的工作数据项数长期由人工协议专家硬编码为 3。这样即使删除生成工具，远程专家仍可独立发送正确的数量和数据；先前的跨家族工具继承并未直接负责构造 B 输入。

S31 不改世界内核、B 协议解析器或权限，修改三份等额初始化的程序：

1. **共用活动 root**：继续 S30 两节点组合图搜索、S30 跨家族失配修复与 S28 的研究者播种的 Len(Bytes) 图改写模板。活动 VM 真实执行 RewriteOp，受费安装不可变程序版本，并通过 WorldCall::Exec 得到公开工作项 values_le 的字节长度。不再简单测试 Len==12；只判断长度是 4 的整数倍，然后由活动 VM 使用 Div(length,4) 和 PackU16Le 生成数量字节，通过受费 WRITE 存入 **/self/work/remote-count-le**。
2. **P1 专家**：原先 S19 在远程工作体中写死的 [17,0,0,0,3,0] 被移除；现在 S19 活动程序读取共享工作对象，将实际数量拼接到请求 ID [17,0,0,0] 和 values_le 之间，交给原有生成的协议 frame 编码器。
3. **P2 专家**：原先 S23/S22 的固定数量 [3,0] 被移除；现在读取同一共享工作对象，把实际两字节数量拼接在 values_le 前，交给原先真实发现并生成的 P2 frame 编码器。
4. 两位专家在装载公开 HELLO 后由共用 root 自主选择并通过受费 CAS 切换到 active，随后都必须 **READ 生成的共享对象**，才能真正对 C 执行 SEND。C/B 不掌握研究者测试中准备的答案，也没有改为假的成功。

## 先记录的因果对照设计

- P1 source seed1 和 P2 target seed19，协议 seed42；初始 root 和同时预安装的 P1/P2 专家包完全相同。P1 在活动 VM 中生成的 S30 组合代码作为真实、收费的导入对象交给 P2，目标仍需验证该组合程序。两个世界的 S28 Len 程序由各自活动 VM 生成并执行；不能将相同 Len 内容哈希本身认作来源继承。
- 正确性验收必须同时包含：**Len 程序的 WRITE 和成功 EXEC，后续生成数量 WRITE，协议专家 READ，同一世界原始 SEND 的有效 C 帧解码显示 count3 + 12字节原始 values_le，真实 B gas20，独立 FOLD32 比较一致**。
- 在 P2 seed19 构建两份根程序、来源工具导入、世界执行记录逐项相同的世界，在 root 完成 count WRITE 并切换专家之后才干预。首先断言干预前 state hash 相等、B gas0、数据版本0；两个臂都由实验宿主执行一次普通受费 WRITE（CAS expected_version0），相同长度的 payload 和完全相同的费用/step：对照写 [3,0]，干预写 [2,0]。注意：这是**研究者反事实介入**，不能说是个体自主遭遇敌意环境后修复。
- 继续原生执行两条轨迹并解码真正的 C SEND：若数据真在远程路径上，前者 body 为 count3+12字节应成功完成 B，后者 body 为 count2+相同12字节应收到 B 服务的 BadBody，B gas0、没有合法远程结果；且变化发生在相同初始状态之后。B 失败组低 A gas 不是效率提升。

## 已验收的原生结果（2026-11-20）

- [**S31 定向 CI #44685083680**](https://github.com/iFrankStudio/OCEE/actions/runs/44685083680)：GitHub Actions **completed/success**，原生 Rust **1 passed，0 failed**，原生核心测试耗时 **50.63秒**。编译、实际状态复制、世界审计、真实协议帧解析和 B 服务拒绝都通过。
- 完全相同初始 root 内容 hash：**398d412d7d5629f14a20289385e278f7073f6a3bc29848341a99a979f6e00be5**。额外的 P1 组合工具 hash **ccbec864ef8a002aa15e07a541cfca57200fa8770f51020274f1b1d359aa43c5**，确实由来源 P1 活动 VM 生成并移植 P2。
- **正常 P1 world seed1**：总 A **12,893 gas**，B **20 gas**，实际 C 帧包含计算得出的 count3，真实独立 FOLD32 正确；**正常 P2 world seed19**：A **24,289**，B **20**，同样发送 count3 并完成远端结果。
- **相同初始状态的 P2 反事实**：干预前包括已生成数量和已选专家的完整世界 state hash 完全相同；两组对 count 对象进行相同一次 CAS WRITE，gas **各3**、数据各2字节、step 同步。继续执行：控制组 **A24,292 / ticks248 / B20**；干预组 **A14,482 / ticks110 / B0**。已直接解码真实 C 报文，确定后者的 RemoteEval 中是 count2+相同12字节 values_le；B 真实报告 BadBody，未产生远程结果。
- A 配额为 **100,000 gas/epoch**，与 S30 同一开发配置，不与 S28/S29 不同 A 配额的绝对 gas 相比较；失败组提前终止不能算省 gas。
- **证据严格范围**：此实验首次证实**活动 VM 自行生成的通用工具结果位于真实 B 请求的必要数据路径**，且 P1/P2 两套人工协议专家可消费同一共享输出约定。直接进入 B 的仍是 S28 **研究者播种的 Len 模板**输出；S30 从 18 候选中选出的多节点组合程序仍承担独立校验任务，**尚未成为 B 数学工作体的必要数据**。不能说 S31 已自主发明新算子、未知协议编码器、现实互联网驱动程序、开放式演化，或确认性 E001/H3 通过。
