# OCEE S35：两样例不可识别性、公开反例与跨家族错误知识的受费纠正

**2026-11-20 · developmental / exploratory · 非 E001 预注册确认。G0 GO，G1/G2 NO-GO。**

## 新研究问题

S34 已证明一个基于研究者封闭语法的活动 VM，可以依据两条公开样例生成4/6/8指令程序，输出真正用于 B 的第四个操作数，并跨 P1/P2 继承。但**两个样例拟合并不保证识别到正确语义**：一条错规则也能通过两个标签，然后参与真实 B 计算。B 的正常执行只证明请求遵守协议，并不证明生成操作数符合环境任务的正确含义。

本实验人为构造可证伪的语义别名：`a=[1]` 和 `b=[2,0]`，均满足 `Len(input)=XorFold(input)=ByteAt(input,0)`，所以基础 S6 组合中 `Len+Len` 与 `XorFold+Len` 的两样例输出一样。然而在未标注的新输入 `[7,8,9]` 上，`Len+Len=6`，`XorFold+Len=9`。在增加0/1/2个 `+Len` 阶段后，别名仍成立，第三输入分别令错误/正确输出为 `(6,9)、(9,12)、(12,15)`。这些数值是研究者事前固定的任务构造，**没有向活动 VM 传隐藏规则或答案**。

## 真实世界机制

1. 使用 S34 原封闭54候选图语法、类型化 AppendInstructions、S30 真实错误继承 CAS 和 S32/S31 真正 C→B 远程 FOLD32 操作数数据通路；所有来源和目标 P1/P2 世界拥有同一份完整初始 root 和等额预装的两位协议专家。研究者测试宿主先在只读 `/public/E001/compose-depth` 发布两组刻意有别名的普通输入/输出标签。
2. 另在一个**精确白名单只读路径** `/public/E001/compose-counterexample` 发布一条额外 `TransformExample{input:[7,8,9],output:...}`。它是测试环境事先给出的第三条训练标签，并**不是 VM 自己发明的反例**；不会被计作未标注 held-out。原来的 `/public/E001/transform.held_out_input` 仍独立产生，并在实验结束后才用隐藏规则核验。
3. 活动 VM 在 candidate 先通过普通两标签比较后，通过受费 `WorldCall::Read` 获得第三条公开标签，真正执行候选 `WorldCall::Exec` 并与标签比较。若不符，恢复正常 bounded loop 到下一候选；若符合，才把内容寻址程序注册并生成真正 B 操作数。原候选版本的受费 WRITE 仍保留，不能说无开销学习。
4. 对已继承的可执行程序也**使用完全相同的第三条标签门控**。因此错误旧程序即使通过前两组公开样例，也不能因 hash/registry 有效而逃过新标签检查；拒绝后从 S30 已有54候选搜索流程重新学习，经真实 CAS 把 registry v0→v1，再继续真实 B。无挑战对象时应**fail closed**，不静默放行。

## 原生判据与对照

- P1 seed1/19/37 → P2 seed55/73/91，分别验证0/1/2次追加阶段。预计候选搜索的真实版本 WRITE 计数（不包含后续单独生成的 S28 Len 程序）分别为**2/20/38**：在本深度的第一个候选会通过两个模糊标签却被第三输入驳倒，第二个同深度候选才通过。来源必须有两次挑战读取，目标正确继承必须有一次挑战读取；两端真实第四个 B 操作数等于独立隐藏规则，B gas24、C 帧及独立 fold32 正确，快照哈希重载一致。
- **没有挑战的旧 S34 学习器消融**：同一个有别名的公共任务，仍可能先选择 `Len+Len`，其输出与隐藏目标不一致；但其真实 C/B 请求合规、B gas24、FOLD32 成功。这个直接展示“服务返回成功”不等于“个体学到正确目标算法”，避免把 S34 既往开发实验证据错误外推。
- **陈旧二样例工具继承**：由原 S34 P1 活动 VM 在上述模糊标签下实际生成的错误程序版本，经正常两次受费 WRITE 导入 S35 P2。目标在旧两个标签下原本会接受它，但挑战标签驳倒，重新从候选语法搜索、注册表真实 CAS v0→v1，使用正确程序完成真正 B 任务。不存在宿主代替 VM 选正确程序。
- **第三标签不可用**：只移除公开挑战对象、保留同样公共前两例和同样安全 ACL；目标应在真正 B 发送前主动停止，B gas0，不得伪造结果；这是一种开发性的 fail-closed 策略，并非任意环境下最优探索政策。
- **同费 sham**：与 P2 两阶段可见继承相同的版本字节、两次受费 WRITE、root、协议、任务与初始世界数据，只修改 Registry 可发现性，双方要能真实完成 B，继承者付出更少 A 搜索开销。相同程序 hash 如果是独立搜索出的，不能冒充来源迁移。

## 严格科学限制

额外第三标签不是独立的最终泛化集；它是环境提供的额外**监督信号**，只能证明有限先验下的反例驱动重新筛选。真实未标注输入的独立正确率仍需与环境隐藏规则作实验后比较。两例不够、三例够只针对刻意构造的当前任务；没有证明三条样例能在任意深度/输入分布上识别算法，也没有实现由 VM 自主提出能最大化信息增益的查询。所有候选语法、三阶段上限、挑战路径、何时验证、重新搜索和协议专家均为研究者编码。仍为本地确定性 C/B，不是开放式赛博生命，E001 G1/G2 继续 NO-GO。
