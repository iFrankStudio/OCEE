# OCEE S37 — 任务指纹绑定的主动探测证据溯源与受费拒绝

**2026-11-20；开发性机制/因果实验，非预注册 E001 确认。现阶段 G0 GO、G1/G2 NO-GO。**

## 起点、风险、研究问题
S36 活动 VM 已能在两个研究者提供的探针输入中选择能区分 Len 与 XorFold 的 `[7,8,9]`，付费向本地世界查询一次，保存返回的 TransformExample，校验自己的候选图后跨 P1/P2 真正参与 B 第四个 U32 计算。然而本地 `/self/evidence/s36-active-probe` 允许个体 Write/CAS，旧 S36 对其来源没有验证。如果该对象在环境查询之前就被放入一个虚假标签，或查询后被覆盖/改写，VM 会把它当作可信标注，程序可能语义错误但 B 正常算术成功。S36 也没有验证当前 `/public/E001/compose-depth` 是否与当初查询对应的任务相同。

**S37 假设**：运行中每次使用缓存标签之前，以真实受费世界动作检验是否存在同世界原始查询记录、缓存字节是否与原始环境回执完全一致，以及公开任务字节是否仍与查询当时的 SHA-256 指纹相同；错误/过期/缺失证据均须 fail-closed、不执行真实 B。正常真实查询和不同深度的跨家族继承应继续成功。

## 实现与权限
- 世界内核持久化可选的 `ProbeRecord{task_hash,receipt}`：一次合法 S36 Probe 成功后，内核保存当时 `/public/E001/compose-depth` 对象字节哈希与其**确实返回的** TransformExample 原始字节。该记录只能由内核成功 Probe 生成，**不能通过普通 `/self/` Write 或公开 Read 伪造/重写**。probe_count 仍维持每世界一次成功查询上限；没有新任意网络访问。
- 通用 VM 增加 `WorldCall::VerifyProbe(Bytes)`，world host 转为真实 `Action::VerifyProbe{evidence}`。内核拒绝超过256字节的输入，对其余每次受费 **2 A gas**；无真实签发记录返回 `NotFound`，与内核原始回执或当前任务 SHA256 不一致返回 `Conflict`，两者均不包含隐藏答案；仅双一致才 `Ok`。持久 `ProbeRecord` 可以通过整个 World snapshot 重载；空记录省略序列化，避免无探针世界的状态字节无意义漂移。此机制是**可信内核内部的原始回执比对，不是外部可验证的密码学签名**。
- S37 从 S36 root 继承同一训练、原始54候选、一次主动 Probe、缓存 WRITE、P1/P2 专家、S30 错误代码 CAS 恢复、S32 远程 B 数值路径。只在两条接受缓存证据的分支上插入真正的 `VerifyProbe` Yield：普通 CACHE READ 命中以及真实 Probe 后 CACHE WRITE 成功后。只有 Verify 返回 Ok，才执行候选图并与该标签比较；否则进入失败终点。每个候选都需要验证，已有自有缓存仍不可绕过。
- 任务版本变化是真实开发环境规则变化：原 v1 oracle 为 `hidden_compose(seed,input)+stages×Len`，研究者可以显式将公开任务对象更换为 `s37-changed-rule-v2` 并修改公开两个样例的标签，此时环境内核的新 oracle 真实改为 `2×Len(input)`。**不允许个体修改公共对象**；这只是研究测试中可重放的外部环境干预。先前成功的 ProbeRecord 与新任务对象字节不同，验证必须失败。现有限额只允许每世界成功查询一次，所以 S37 的安全选择是拒绝继续，**不是已经实现自主重新购买配额或自适应学习变化后的规则**。

## 可证伪对照（必须在原生世界通过，不可只检查哈希或文本）
- 正常 P1 seed1/19/37 → P2 seed55/73/91，三类0/1/2阶段：双方仍实际自主 Probe 一次、付费52 A/保存证据一次，来源两个两样例拟合候选均经内核真实 VerifyProbe，每次2 A；目标继承正确图时验证1次；真实目标未标注新输入的第四U32正确、C帧及远程B24、快照恢复正确。等费可见继承/sham与来源旧错工具CAS修复也应保持完整语义正确，且用于候选比较的缓存每次经过内核验证。
- **凭空伪造标签**：通过普通受费自有对象 Write 预先安装标签 `input=[7,8,9],output=6`，并不给世界任何真实 Probe。旧 S36 可以接受该标签，在真实远程 B 成功的同时得到错误第四数；S37 内核不存在签发记录，预期 VerifyProbe `NotFound`、不产生 B 请求、B0。
- **查询后缓存篡改**：让两个对照世界自行成功 Probe 并 WRITE 正确缓存，再由研究者模拟对缓存执行**真实收费 CAS**将 `[7,8,9]` 标签覆盖为10。第一错误候选此前的原始回执应被拒绝；后续候选 READ 污染的缓存时，S37 必须遇 `Conflict`、B0；旧 S36 则可能选择后续某个错误候选而真实 B24，隐藏语义错误。这项干预是宿主模拟攻击，不计作个体主动攻击。
- **任务规则变化**：在成功 Probe/保存缓存之后，研究者将任务对象变为 v2（真实环境 oracle 改为 `2×Len`）而不改变来源根的状态机或已签发证据；S37 Verify 必须 Conflict、B0，旧 S36 应仍继续 B24，但程序的第四数不符合当前环境规则。再次向 v2 Probe 应由于单世界已有一次成功而 Quota；此研究不声称能重新学习新规则。
- **内核独立检查**：无签发→NotFound（收取2 A），真实 Probe→可验证原回执Ok，单字节/标签差异→Conflict，过长输入→BadRequest；保存/还原完整快照后记录字节一致；任务变化导致已签发回执失效。

## 科学限制与下一门槛
此实验的任务、比较策略、隐藏规则、变化时机、伪造事件均由研究者预置，内核在模拟世界中拥有可靠元数据。`VerifyProbe` 是受费的二值等值接口，**不是密码学不可伪造签名**，大量猜测仍可能获得可观察的验证反馈；而防御更多意/并发世界状态更替、合法任务版本升级后重新取得查询预算、自主识别跨版本兼容的证据都未实现。全部仍为本地模拟 C/B，不能视为互联网适应能力或开放式赛博生命。G0 GO；G1/G2 NO-GO。后续可以研究服务端签发短期任务授权/真正加密的证据凭证、任务版本变更后的安全再查询和资源决策。
