## 假说

上一阶段的 S3 虽能生成新工具版本，但研究者事先提供了完整工具算法模板，而且初始自测试只检查 EXEC 是否返回 Ok。S4 检验更严格的命题：一个个体能否在**可执行但功能错误**的候选被拒后，自行改变程序图的操作符、重新验证，并且仅保留功能正确的版本。

## 执行机制

1. 个体从公开环境与 P0 诊断反馈发现当前隐藏 REMOTE_EVAL opcode。
2. 生成第一个可执行报文构造程序：校验和节点错误地使用 `Len(5)`，类型检查及 EXEC 都可成功，但生成的实际校验和错误。
3. 在活动 VM 内构造参考测试帧，并比较候选 EXEC 的真实**输出字节**；拒绝无效结果，不能以 EXEC Ok 代替功能判断。
4. 通过 VM 通用 `RewriteOp(program_json, block_id, instruction_id, replacement_op_json)`，将第 6 号节点由 Len 改为 XorFold，再次静态校验、构造内容哈希和不可变版本。
5. 全部候选路径经 `RepeatBounded(limit=2)` 约束，禁止无界循环。第二候选通过功能校验后，个体自行注册、调用工具，构造公开工作项并经 C 使用 B，保存服务反馈。

通用 RewriteOp **不包含 P0、XOR 或 FOLD32 专用识别与自动选择**：只提供类型安全的结构编辑操作；具体改写哪个节点、改成什么算法、如何验证，全部由可审计个体程序决定并受世界资源计费。

## 已通过的验证

| 开发条件 | 种子 | 结果 |
|---|---|---|
| 有界结构修复 | 7、42 | 错误候选与成功候选均存入版本库，只有后者被注册并用于真实 B 计算，状态快照重放一致 |
| 关闭结构修复 | 7 | 错误候选仍可执行，但没有工具被注册，也没有 B 的有效计算 |
| S3 功能负对照 | 7 | 错误候选可返回 EXEC Ok；实际字节校验阻止其注册 |
| VM 类型约束 | 独立测试 | 通用图编辑能更改实际语义，但会拒绝类型不兼容的新操作符 |

开发实验使用 `100000 A gas/epoch`；**不能**推断在 E001 规定的 `12000 A gas/epoch` 下同样可行。当前也没有跨 episode 累积或跨 P1/P2 协议结构迁移证据。

## 能力归因边界

**初始赋予**：P0 XOR 帧结构、两种候选操作符 Len/XorFold、固定两次尝试策略、正确输出的测试路径、通用程序 JSON 拼装与图编辑能力。事实上，初始程序的校验器本身就使用了 XorFold 原语。

**运行时实际获得**：当前环境未知 opcode、不同候选的功能差异、结构改写后有效程序的内容哈希、后续受理和资源使用反馈。

因此，本研究支持 **在给定搜索空间内、反馈驱动的单节点结构修改与功能筛选**，不是从零发明全新算法、开放式演化，也不是数字生命已经出现的证明。

## 下一道研究闸门

优先检验未在初始程序中给出完整修复顺序的更大搜索空间，以及标准资源约束；然后推进未知 P1/P2 协议、不同结构间迁移、跨 episode 保留能力和 E001 四组正式对照。G1 / G2 均维持 **NO-GO**。
