## 假说与流程

S7 预先给出正确的空输入守卫算法，S8 在同样的 S6 组合任务里，测试个体能否生成**两个合法可执行修复候选**，根据实际错误输入的功能结果选择，而非直接采用第一份能运行的补丁。

1. 初始 VM 首先独立完成 S6 有限语法工具生成与注册，之后执行空输入探针；若旧工具返回 InvalidCode，个体保存真实故障记录，并 READ 原工具版本。
2. 进入 RepeatBounded(limit=2) 搜索循环。第一次 PrependBlocks 构造控制流守卫，RewriteOp 将空输入返回值设为 1；该候选语法、类型和隔离执行均有效，但观察到的数值不符合已给定的目标 0，因此不会采用。
3. 从未修改的原工具再次构造候选，把相同守卫的返回值改为 0；个体隔离 EXEC 验证空输入以及公开非空训练样例回归结果。
4. 只有通过两层功能检查，才以 CAS 将工具引用从对象版本 0 更新为版本 1。错误候选、正确候选及原工具都以不可变程序版本保留，活动 VM 初始程序从未由研究者更换。

## 科学归因、负面限制

**研究者预置的知识**：S6 的有限语法和搜索程序、空输入探针及故障码处理、固定的守卫块语法、修复值词表 [1,0]、固定先后顺序、两次搜索上限、以及“空输入正确结果应为 0”的比较器和非空回归规则。

**运行时实际得到的行为**：个体由真实故障驱动，在一个连续 VM 生命周期中建立两个不同可执行候选，通过执行反馈排除功能错误者，生成通过验证的第二个版本，并原子采用及保留历史。

仅从两个非空标注样例以及一个空输入故障，**不能逻辑推导**空输入正确返回值必然为 0；与非空训练结果一致而空输入返回 1 的目标函数同样可能存在。S8 的成功依赖预置的正确答案比较规则，故**不能声称新修复算法独立起源**，不能视为开放式演化、真正未知 P1/P2 协议学习或 E001 M0 达成。
